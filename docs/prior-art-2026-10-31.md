# Prior art

Several open-source tools already give guided PR tours. None found so far describes the full Docent loop: live questions to the author's own session, an independent guide checking the answers, batched revisions back to the agent, and swappable vendor adapters.

Everything here comes from project descriptions found on October 31, 2026, not hands-on testing. Screenshots are in each project's README; open the links to compare visuals.

| Project                                                                | What it is                                    | Overlap with Docent                                                                                                                   | Not seen in its description                                                             |
| ---------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| [JiwonKKang/loupe](https://github.com/JiwonKKang/loupe)                | macOS desktop app (Tauri, React, Rust), v0.5  | Reorders a PR into data-flow order, walks through one symbol card at a time, AI clustering, read-only inline Q&A grounded in the repo | Answers from the author's session, batched revisions back to the agent, vendor adapters |
| [thomas783/pr-docent](https://github.com/thomas783/pr-docent)          | Chrome extension on GitHub PR pages           | Guided, narrated review tours; runs on your local Claude Code subscription via `npx`, no API key                                      | Standalone review UI, author Q&A, revisions, code map                                   |
| [vivecuervo7/docent](https://github.com/vivecuervo7/docent)            | Local tool for large PRs                      | Splits a PR into small explained slices and walks through them, starting from an overview                                             | Author Q&A, revisions, independent answer checks                                        |

**Closest matches:** JiwonKKang/loupe for the tour and inline Q&A, and thomas783/pr-docent for the local, bring-your-own-subscription model.

## Next step

For each of the top three, check the README screenshots, recent commit activity, license, and whether the maintainer accepts contributions. Then score each against the brief's must-haves. If one covers most of them, contribute there; if none do, the gaps above are the reason to build Docent.

## Ideas to judge for the brief

Three findings from prior art, pending a decision on each.

- [ ] **Verified, self-healing line anchors** ([h0w4r/waymark](https://github.com/h0w4r/waymark)). Each map node stores its exact line content, is checked against the code, and re-anchors when code moves; `waymark verify --strict` flags stale maps in CI. Would harden Docent's "every claim cites lines" rule.
- [ ] **Commit-keyed cache and per-job models** ([JiwonKKang/loupe](https://github.com/JiwonKKang/loupe)). Unchanged ranges reuse a SHA-keyed cache with zero AI calls; a stronger model orders the tour while a cheaper one writes labels. Supports the cost goal.
- [ ] **GitHub's diff-line rule** ([tcpmia/loupe](https://github.com/tcpmia/loupe)). An inline comment on a line outside the diff makes GitHub reject the whole review. Suggestions on adjacent files need a fallback: snap to the nearest changed line or move to the review summary.

Also noted: [thomas783/pr-docent](https://github.com/thomas783/pr-docent) ships as a browser extension on the GitHub PR page, a possible lightweight entry point.
