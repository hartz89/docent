# Decisions

Calls that are the maintainer's, batched so they don't block work. The rules are in AGENTS.md, under "Decisions". Once a decision is answered, it moves out of this file and into the doc or code it affects.

## Open

- **npm scope for publishing.** Settle before the first npm release. "Docent" is the name (decided below), but the unscoped npm name is taken, so the package ships scoped (`@<scope>/docent`) with a `docent` command. Background: "Docent" is the working name. Two similar projects already use it ([vivecuervo7/docent](https://github.com/vivecuervo7/docent), [thomas783/pr-docent](https://github.com/thomas783/pr-docent)), and the unscoped `docent` package on npm is taken by an unrelated placeholder. This becomes hard to reverse at the first public release. Until then, packages use the `@docent/*` scope privately.

## Done, reversible

- **2026-11-12 · PR descriptions keep their visible part to about 300 words** (tier 2a, in `docs/process/pull-requests.md`). Before this, open PRs ran from 370 to 3,070 words, and the maintainer said they were too long to read. Detail and known gaps go in collapsed `<details>` sections. Undo by deleting that paragraph.
- **2026-11-11 · The answer check runs on Haiku 5.5, and fails silent.** After the author's session answers, the guide checks the answer against the head checkout, read-only, and shows a note only when the code plainly contradicts it, with citations that pass the tour's citation check (all of them, or the note is dropped). An error, a timeout (90 s) or a malformed reply means silence, never a warning: the guide explains, it doesn't grade. On a small eval (15 distinct answers, 4 runs each), Haiku caught all 6 wrong answers in 23 of 24 tries and never flagged any of the 9 right ones, at about $0.001 a check. Nine right answers is too few to pin the false-alarm rate down ([`../docs/research/2026-11-11-answer-check.md`](../docs/research/2026-11-11-answer-check.md)). Raise `DEFAULT_CHECK_MODEL` in `apps/server/src/answer-check.ts` if real answers show misses.
- **2026-11-10 · Harness evals v1.** A context-footprint budget in `pnpm verify` (characters / 4, budget 1,580 tokens, about 15% over today's 1,368), and `pnpm bench:harness`: six mechanically graded tasks, base against branch, in `git archive` copies with sandboxed Bash, capped by `--max-usd` (default $3). The runner lives in `scripts/`, not `packages/evals`, until the product evals need it too; then they share one. Undo by reverting the PR.
- **2026-11-10 · v1 ships as one npm package, built by `pnpm pack:cli`.** The server and CLI are bundled with `@docent/core` (rolldown), the built web app rides along, and the remaining npm dependencies (the Agent SDK, `hono`, `@hono/node-server`) install at exact versions, with an `npm-shrinkwrap.json` pinning the whole tree. The scope is a placeholder, `@docent`, set only by `NPM_SCOPE` in `scripts/pack.ts`, until the open scope decision above is made. Publishing is the maintainer's: [`docs/release/checklist.md`](../docs/release/checklist.md). Licenses outside MIT/Apache/BSD/ISC are allowed only by name, with a reason, in `scripts/check-deps.ts`: the Agent SDK (Anthropic's terms), the three fonts (SIL OFL 1.1) and two Unlicense packages. Rejected: publishing `@docent/core` and `@docent/server` separately (three packages to version for one CLI), and bundling every dependency (the Agent SDK's terms don't clearly allow redistributing it inside ours).
- **2026-11-08 · Questions find the author's session from the PR's `Claude-Session:` link, or `--session <id>`.** The link names the session on claude.ai, not on disk, but the local transcript records it when remote control starts (a `bridge_status` entry). So Docent scans this machine's transcripts for that record, earliest-started first, since forks copy it. Links are public, so a link alone never picks a session: one of the transcript's own records (its session id matching the file) must show it on the PR's head branch in a checkout whose origin is the PR's repo, branch and folder from the same record, and the head branch must live in that repo (not a fork), so only someone with push access could have made it. Otherwise the guide answers ("the linked session doesn't match this PR"). `--session` is the reviewer's own choice and isn't checked against the PR. It works today on this repo's own PRs with no new tooling. It only finds sessions started with remote control on, on this machine; a session-ID hook (the brief's plan) or snapshots would lift both limits. Rejected for v1: a new PR-body convention nobody writes yet.
- **2026-11-08 · A failed fork falls back to the guide; the answer says why and records both costs.** The reviewer still gets an answer, labeled as the guide's. The alternative, showing an error, makes the reviewer retry into the same failure.
- **2026-11-08 · A fork is skipped when its first call is estimated over $2 (`--fork-budget`).** The estimate is the session's last context size, cache-written at 2x input: Claude Code writes 1-hour cache entries on a subscription by default, and PR #17's measured $1.63 matches 2x. The budget is also the fork's own spending cap, so an estimate that passes is never cut off by a lower one. A fork that hits the cap or times out turns questions over to the guide for the rest of the review, including questions already waiting. At the default, a ~250k-token Opus session (about $2.00) is right at the line; raise `--fork-budget` to ask it anyway.
- **2026-11-08 · Questions to one author session queue rather than being refused,** up to 3 waiting, then a 429. Each answer times out after 3 minutes, and a reviewer who leaves aborts the fork. Forks don't share state, so concurrency would be safe, but a queue keeps a burst of questions from forking a large transcript many times at once, and answers arrive in the order asked. The lock is in-process and per session id. Forks set `persistSession: false`, so no fork transcript is left to clean up.

- **2026-11-07 · Agent containment: attribution for now (option A).** Agents act through the builder and reviewer GitHub Apps, and the `main` ruleset has no bypass for anyone. Agents still run as the maintainer's macOS user, so the apps record who acted but can't stop a misbehaving agent; GitHub's ruleset is the real boundary. Revisit when sessions move to the cloud, where agents only ever hold an app token. Rejected for now: a separate macOS user (B), cloud or container sessions (C).
- **2026-11-07 · Tier 2 split into 2a (contracts and dependencies that don't touch security: agents merge after a clean fresh-context review) and 2b (security, permissions, CI, the harness and the rules themselves: the maintainer).** Following the maintainer's direction to merge autonomously within the gates. Undo by merging 2a back into 2b in pull-requests.md. Superseded on 2026-11-10: only a rare escalated PR waits for the maintainer now (see "Decided by the maintainer").
- **2026-11-06 · License: Apache-2.0.** It includes an explicit patent grant, and its contribution terms (section 5) suit a project that wants community-built vendor adapters. The maintainer's other repos use MIT, which would also have been fine. This is easy to change until the first outside contribution lands; after that it needs contributors' consent.
- **2026-11-06 · Eval fixtures from private repos stay out of this public repo.** They describe private code. The plan: a private fixtures repo of manifests (repo, SHAs, expected findings), fetched at run time, plus a committed public core set built from open-source PRs. See [`../docs/research/2026-11-06-eval-fixtures.md`](../docs/research/2026-11-06-eval-fixtures.md).

- **2026-11-07 · The `docent` CLI lives in `apps/server` (`src/cli.ts`), not a new `apps/cli`.** It only parses arguments, wires the GitHub and model boundaries, and starts the server, which already owns startup. A separate package would add a workspace, a tsconfig and a dependency edge for about 100 lines. Split it out when it grows commands that don't start the server.
- **2026-11-07 · The tour's default model is `claude-opus-5-5`.** One real run on a 78-line PR cost $0.06 to $0.13. Override with `--model` or `DOCENT_MODEL`.
- **2026-11-07 · Tour cost comes from the result message's `usage`, priced with a list-price table in `apps/server/src/agent.ts`.** Assistant frames carry a start-of-stream usage snapshot (output tokens near zero), and `total_cost_usd` includes the parent session on resumes. The table needs updating when prices change.

## Decided by the maintainer

- **2026-11-10 · No code owners; escalation to the maintainer is rare, at most two waiting.** Our own agents are trusted. The gates guard against outside input (a PR's own code, other websites), not against our own agents. Any owned path made the maintainer a bottleneck, so `.github/CODEOWNERS` is gone. The `main` ruleset requires green CI and no approvals: required approvals can't work yet, because the builder's session can't approve its own PR and the reviewer app has no write access. The agent review is posted before auto-merge is queued, as a practice. A GitHub-enforced agent gate comes later: an independent reviewer, outside the builder's session, posting a required status check (the reviewer app needs Checks: write). Tier 2b means a security-focused agent review, picked by the reviewer's checklist with a path floor (all of `apps/server/src/` except tests, since a backtest showed PRs like #19 fell to 2a without it); it doesn't involve the maintainer. Escalation is separate: only for a change that grants agents new powers, acts as the maintainer in a new way, weakens a gate, or leaves a security concern or a product or values call unresolved. Expect roughly one per session, as an expectation, not a quota. In the maintainer's words: "some escalations to me are fine, and they're a useful way to dogfood docent, but i don't want to walk into a 5-deep stack of pull requests every time i revive a session." So: at most two escalated PRs wait at once (a third is labeled `escalation-queued` until a slot frees, since the builder can't toggle drafts), nobody stacks on a waiting PR, each arrives with a Docent tour, and it's queued for merge only after the maintainer approves. Escalated PRs carry the `needs-maintainer` label. Harness changes still pass the harness evals. The ceiling on agent power is each GitHub App's permissions, which only the maintainer can change. Replaces the tier 2b rule from 2026-11-07 that sent security, CI and harness PRs to the maintainer.
- **2026-11-06 · Stack:** Hono server, Vite + React + TanStack Router/Query web app, TypeScript 7, pnpm. Chosen on agentic legibility, performance and product fit; familiarity didn't count.
- **2026-11-06 · Open source from day one.**
- **2026-11-06 · Name: keep "Docent."** Chosen in decision brief no. 1, option A. The metaphor carries the product's idea; the npm package will be scoped.
- **2026-11-09 · The product has no risk tiers.** Docent never rates, labels or routes a PR by risk. How much review a PR needs is up to the org that owns it. Risk tiers stay in how *this repo* merges its own PRs (`scripts/tier.ts`, `docs/process/pull-requests.md`); that's dev environment, not product.
- **2026-11-09 · The skip ledger is computed, not written.** Every changed line stays visible: on the route, a proven skip that a script labels, or "not on the route". The checker builds the list, and the docent no longer has to cite or skip every line. A model-written skip reason is the easiest thing for an injected comment to fake, and requiring one forced noise (cited import blocks, stops on barrels) and retries. Backlog item 6 carries it out.
